Wishaw UI Backend API Reference

UI-facing API contract generated from the implemented backend controllers, DTOs, Spring Security rules, and the React service layer. All example paths use /api because the UI defaults to that base. The backend also exposes the same routes under /api/v1.

Generated March 30, 2026
Canonical Base URL VITE_API_BASE_URL=/api
UI Mock Switch VITE_USE_MOCKS=false
Auth Model Bearer access token + refresh token

Integration Rules

Headers and Authentication

  • Send Authorization: Bearer <accessToken> on every authenticated request.
  • Use Content-Type: application/json for all write endpoints except photo upload.
  • Photo upload uses multipart/form-data with a single file part named photo.
  • The backend exposes X-Correlation-Id in responses for tracing.

Refresh and Error Handling

  • If an authenticated call returns 401 with code: "TOKEN_EXPIRED", post the refresh token to /api/auth/refresh and retry once.
  • All backend errors use the same JSON envelope shown below.
  • The React client already expects error text from the HTTP body when present and falls back to HTTP {status}.
Canonical UI base: /api Versioned alias: /api/v1 Public only: login, register, refresh Admin-only writes called out below

Endpoint Matrix

The "UI Method" column maps directly to the methods in the React API client. Request and response schema names are detailed later in this document.

Auth and Session

UI Method Method Path Auth Request Response Notes
realApi.login POST /api/auth/login Public LoginRequest AuthResponseDto Returns access token, refresh token, user, and profile in one response.
realApi.register POST /api/auth/register Public RegisterRequest AuthResponseDto Creates a player account by default.

realApi.getMe GET /api/auth/me Bearer token none SessionDto Used during app bootstrap to restore session state.

Enums and Integration Notes

Enums Used in Payloads

  • UserRole: PLAYER, ADMIN, SUPER_ADMIN
  • TournamentStatus: DRAFT, PUBLISHED, CANCELLED, COMPLETED
  • TournamentType: INDIVIDUAL, TEAM
  • ParticipantStatus: REGISTERED, WITHDRAWN
  • AttendanceStatus: PRESENT, ABSENT, LATE, EXCUSED
  • MatchStatus: SCHEDULED, IN_PROGRESS, COMPLETED, WALKOVER
  • BadgeLevel: None, Bronze, Silver, Gold, Platinum

Observed Contract Gaps

  • realApi.getTournaments(filters) can send query params, but the backend currently ignores them.
  • getGallery is implemented as a tournament existence check plus an empty array.
  • getShareData has special handling only for type=tournament.
  • assignBadge and createAnnouncement are authenticated but not admin-gated in the current security config.
  • uploadPhoto returns a generated data URI, not a persisted asset URL.
Recommended frontend dev configuration
Use VITE_USE_MOCKS=false and point VITE_API_BASE_URL to http://localhost:8080/api when testing against the Spring Boot service locally.
Versioned routing
If you prefer the versioned contract, replace every /api/... example in this document with /api/v1/.... The backend maps both forms today.
